- **Fixed:** Diagnostics for a file now see edits made on disk to the other documents Pyright has open: before analysis the server resynchronizes every changed open dependency (unchanged files cost one `stat`; deleted or unreadable ones are closed instead of failing the call), and `get_workspace_diagnostics` and `get_diagnostics(file_paths=...)` do this once per batch. A large external change set is resynchronized under the 5 s request timeout, so a very large one can time out the first call; the retry resumes where it stopped. `get_workspace_diagnostics` and `dead_code_detection` now propagate cancellation instead of reporting it as a per-file scan failure. A change is detected by the file's modification time and size, so an edit that keeps both identical is not noticed until the file changes again.
