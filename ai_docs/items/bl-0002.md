## Acceptance

- [ ] `rename_symbol{new_name:"   "}` returns a tool error naming `new_name` and the reason (today: bare `Error executing tool rename_symbol`)
- [ ] `check_type_stub_freshness` with no adjacent `.pyi` returns a clear "stub file not found" error
- [ ] `apply_code_action` at a position with no actions returns an empty list, matching its description

## Evidence

- 111 calls across 33 tools returned the bare `Error executing tool <name>` (incl. valid `apply_code_action` / `check_type_stub_freshness` calls); the reason exists only in server stderr. — see `audit-reports/20260923-2310_jedi-py-mcp_mcp-surface-audit.md` and `ai_docs/audits/20260923-2310/`

## Context

- Root cause: `tool_error_boundary` catches only `BackendError`; the MCP SDK replaces every other exception with `UnexpectedToolError`, dropping the message. Keep the redaction contract for genuine backend failures; add an explicit caller-safe error class whose message is surfaced.
