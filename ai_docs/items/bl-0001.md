# bl-0001 — dead_code_detection reports every once-referenced symbol as dead

**row:** `bl-0001` · **pri:** `Medium` · **size:** `S`

## Anchors

- `src/python_refactor_mcp/tools/search/dead_code.py:59-63` (`pyright.get_references(..., False)` — declaration excluded)

## Acceptance

- [ ] A private helper defined once and called once in the same file is NOT reported dead; a helper with zero call sites still is (fixture pair in `tests/unit/test_search_tools.py`)
- [ ] `dead_code_detection` on `src/` of this repo drops from 306 items to a number a maintainer can review; the remaining items are spot-checked live
- [ ] The threshold and the `include_declaration` argument are documented together at the call site so they cannot drift apart again

## Evidence

- 2026-09-02 `/refactor-audit depth=shallow` smoke of this repo: `dead_code_detection` returned 306 items on `src/` (337 repo-wide), every one `reason: "no references"`. Spot-checks all live: `_filter_type_ignore` (`backends/pyright_lsp.py:64`, called `:504`), `_reconstruct_symbol_hierarchy` (`:140` → `:651`), `_OP_DISPATCH` (`backends/rope_backend.py:114` → `:128`), `_profile_includes` (`tool_registry.py:1736` → `:1756`).
- Root cause: references are fetched with `include_declaration=False`, so a symbol with exactly one in-file use yields `same_file_count == 1`, which the `> 1` test treats as "only the declaration".

## Context

- `/refactor-audit` lists this tool as a Tier 1 input for the DeadCode dimension (`~/.claude/prompts/refactor-audit.md` §4); until fixed the prompt's "spot-check ≥3 items per tool" rule is what keeps it from flooding backlogs. One-line fix (`>= 1`, or pass `True` and keep `> 1`) plus one fixture-pair test; regression shape: the once-used helper case.
